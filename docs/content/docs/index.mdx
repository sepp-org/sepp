## What is a job queue?

A job queue is a system that allows producers to enqueue jobs for workers to complete in an asynchronous manner, including across different
programming languages. For example, a Rust backend service might schedule a job to send an email, which is then picked up by a Python worker
that has access to a SMTP server. Durable job queues like sepp persist these jobs onto disk so that they are not lost in the event of a 
server crash or restart.

## Core feature map

- **Fully durable by default** — every job is persisted to disk before responding. [Durability](/docs/operations/configuration)
- **At-least-once delivery** — leased jobs return to ready if a worker dies. [Delivery guarantees](/docs/concepts/job-lifecycle#delivery-guarantees)
- **Priority & scheduling** — run-at timestamps and per-job priority. [Scheduling](/docs/concepts/priority-and-scheduling)
- **Retries & dead-letter** — bounded retries, then sideline for inspection. [Retries](/docs/concepts/retries-and-dead-letter)
- **Idempotent enqueue** — dedup keys collapse duplicate producers. [Idempotency](/docs/concepts/idempotency-and-dedup)
- **Language-agnostic** — one gRPC line protocol, any client. [Build your own](/docs/clients/build-your-own)
- **Built-in admin UI** — real-time server state, job inspection, configuration and more. **_Coming soon_**
