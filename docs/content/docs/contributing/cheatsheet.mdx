## Frontmatter

Every page starts with a YAML block. The two keys actually used are `title`
(shown in the H1, sidebar, and search) and `description` (shown as the lead
paragraph and in `<meta>` tags).

```mdx
---
title: My page
description: One-line summary, also indexed by search.
---
```

## Headings

Use plain `#`, `##`, `###`. Fumadocs auto-generates ids and wraps each heading
in an anchor link — hover any heading to see the chain icon. The right-rail
TOC is built from H2 and H3 entries.

```md
## A second-level heading
### A third-level heading
#### A fourth-level heading
```

### Third-level example

#### Fourth-level example

## Paragraph text & inline emphasis

Lorem ipsum dolor sit amet. **Bold text** carries weight; *italic text*
whispers; ~~strikethrough~~ marks a retraction. Use `inline code` for short
identifiers, file names like `Cargo.toml`, or short shell snippets like
`cargo build --release`. Long passages just wrap normally — line length is
clamped at 760 px so reading stays comfortable.

```md
**bold**, *italic*, ~~strikethrough~~, `inline code`
```

## Links

Internal links use the same path the file lives at:

- A [link to itself](/docs/cheatsheet) (same page)
- A [link to the docs root](/docs) (index)

External links open the same way:

- [Fumadocs](https://fumadocs.dev), [Next.js](https://nextjs.org).

```md
[Internal](/docs/cheatsheet)
[External](https://fumadocs.dev)
```

## Callouts

Three flavors, each with its own palette. The `title` prop is optional.

```mdx
<Callout type="note" title="Heads up">
Lorem ipsum dolor sit amet.
</Callout>
```

<Callout type="note" title="Heads up">
Lorem ipsum dolor sit amet, consectetur adipiscing elit. Use **note** for
neutral asides — context that's helpful but not urgent.
</Callout>

<Callout type="info" title="Good to know">
Use **info** for tips, configuration hints, or "here's how this actually
works" explanations.
</Callout>

<Callout type="warn" title="Be careful">
Use **warn** for footguns, breaking changes, and irreversible operations.
</Callout>

## Steps

A numbered, vertically-connected walkthrough. Each `<Step>` is one item.

```mdx

    Lorem ipsum…
  </Step>
  <Step>
    ### Then do this
    Dolor sit amet…
  </Step>
</Steps>
```

    ### Install
    Pull the binary from the releases page, or `cargo install sepp`.
  </Step>
  <Step>

    `sepp --bind 127.0.0.1:11400`. The server logs `ready` once the WAL is
    open.
  </Step>
  <Step>
    ### Connect
    Use your favorite client — every first-party client speaks the same
    line protocol.
  </Step>
</Steps>

## Accordion

Collapsible sections — useful for FAQs or "advanced configuration".

```mdx
<Accordions>
  <Accordion title="What is Sepp?">
    A job queue server.
  </Accordion>
</Accordions>
```

<Accordions>
  <Accordion title="What does the WAL contain?">
    Every state-changing operation in insertion order — `put`, `reserve`,
    `ack`, `bury`, `kick`. On restart, Sepp replays the log to rebuild
    in-memory state.
  </Accordion>
  <Accordion title="Can I run Sepp in a container?">
    Yes — the multi-arch image is at `ghcr.io/sepp-org/sepp`. Mount a volume
    at `/var/lib/sepp` to keep the WAL across restarts.
  </Accordion>
  <Accordion title="Is there a cluster mode?">
    Not in the 0.x series. Run a single node behind your supervisor of choice
    and use multiple tubes for sharding.
  </Accordion>
</Accordions>

## Table

Standard pipe-syntax. Fumadocs styles them automatically.

```md
| Column A | Column B | Column C |
| -------- | -------- | -------- |
| cell 1   | cell 2   | cell 3   |
```

| Verb       | Side       | What it does                                  |
| ---------- | ---------- | --------------------------------------------- |
| `put`      | Producer   | Append a job to the current tube.             |
| `reserve`  | Worker     | Take the next ready job for the lease.        |
| `ack`      | Worker     | Mark the reserved job done; remove from tube. |
| `release`  | Worker     | Hand the reservation back voluntarily.        |
| `bury`     | Worker     | Sideline a job for manual inspection.         |
| `kick`     | Operator   | Move buried jobs back to ready.               |

## Navigation between pages

To link to another doc, use the path relative to the site root:

```md
Read [the cheatsheet](/docs/cheatsheet) for examples.
```

Sidebar order is controlled by `content/docs/meta.json`:

```json title="content/docs/meta.json"
{
  "title": "Docs",
  "root": true,
  "pages": ["getting-started", "concepts", "clients"]
}
```

Each subfolder gets its own `meta.json` with a `title` (shown as the section
eyebrow) and a `pages` array listing the file slugs in render order.

## Page footer (prev / next)

Fumadocs auto-generates the prev/next pager from the sidebar tree — no
action needed in the MDX file itself.
