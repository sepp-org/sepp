A lease is sepp's answer to a simple question: if a worker takes a job and then vanishes, how does the job ever get done? Every reservation hands the worker a job *and* a deadline. Keep the deadline by acking, nacking or extending in time and the job is yours; miss it and sepp assumes you are gone and gives the job to someone else. That one mechanism is what makes delivery at-least-once.

## Reserve and the lease

A worker gets work by reserving it. You give `reserve` the queues to pull from and a lease duration, and it long-polls: it returns as soon as a job is ready or after the wait timeout with nothing if the queues stay empty. Queues are tried in order, so list the most important first. By default you get a single job; ask for a batch with `max_jobs`.

Reserving moves each job to in-flight, starts its lease clock and hides it from every other worker until the lease ends, so exactly one worker holds a job at a time. Each job arrives with a `ctx` carrying its `id`, the `attempt` number (1 on the first delivery), `max_attempts`, and the lease expiry, the wall-clock instant your hold runs out.

<LangTabs items={['Rust', 'Python', 'TypeScript']} groupId="reserve">

```rust
use std::time::Duration;
use sepp_rs::client::SeppClient;
use sepp_rs::ReserveOptions;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = SeppClient::connect("http://localhost:50051").await?;

    // Pull up to 10 jobs, "emails" first then "checkout", each leased for 30s.
    // Wait up to 5s for the first job to show up.
    let opts = ReserveOptions::new(["emails", "checkout"], Duration::from_secs(30))?
        .with_max_jobs(10)
        .with_wait_timeout(Duration::from_secs(5));

    // A long poll: Some(jobs) holds at least one job; None means the wait
    // elapsed with nothing ready, so you just reserve again.
    if let Some(jobs) = client.reserve(&opts).await? {
        for job in &jobs {
            println!(
                "leased {} (attempt {}/{}), lease until {:?}",
                job.ctx.id, job.ctx.attempt, job.ctx.max_attempts, job.ctx.lease_expires_at,
            );
        }
    }
    Ok(())
}
```

## Lease duration and clamping

The lease duration you pass is a request, not a guarantee. Each queue has a `max_lease_duration` the server will not exceed and `reserve` clamps your request down to it. When you reserve from several queues at once, the cap is the smallest max among them, since the response can hold jobs from any of them. Clamping is silent: asking for longer than the max is not an error, you simply get the max back.

So never assume your lease lasts exactly as long as you asked. The lease expiry on each job's `ctx` is the server's authoritative answer and the effective max is advertised in the server capabilities (`GetServerInfo`) if you want to know it up front.

<Callout type="info" title="Trust the expiry, not the request">
The lease expiry carried on `ctx` is the real deadline, after any clamping. Budget your handler against that, not against the duration you asked for.
</Callout>

## Extending a lease

Some jobs take longer than any sensible lease. Rather than reserving with a huge lease (which the queue cap would clamp anyway and which would delay redelivery when a worker really does die), keep a short lease and push it out while you work. `ctx.extend` moves the deadline to a fresh duration measured from now and returns the new expiry, clamped to the queue max just like `reserve`.

The `Worker` can do this for you on a heartbeat with auto-extend; call `extend` yourself when you would rather renew at explicit checkpoints, such as between the chunks of a big job. See [your first worker](/docs/get-started/first-worker#concurrency-and-long-running-jobs) for the auto-extend setup.

A failed extend is information, not just an error. If it comes back as a lost lease (covered in [attempt fencing](#attempt-fencing-failed_precondition-vs-not_found) below), the job has already moved on to another worker, so the right move is to stop rather than finish work that no longer counts.

<LangTabs items={['Rust', 'Python', 'TypeScript']} groupId="extend">

```rust
use std::time::Duration;
use sepp_rs::client::LeaseError;
use sepp_rs::worker::HandlerError;

// A handler for a long job, renewing its own lease between chunks.
.handle("import", |payload, ctx| async move {
    for chunk in chunks(&payload) {
        process_chunk(chunk).await;
        match ctx.extend(Duration::from_secs(30)).await {
            // The new expiry reflects any clamping to the queue's max.
            Ok(expires) => println!("lease renewed until {expires:?}"),
            // The lease is already gone; stop instead of working twice.
            Err(LeaseError::JobNotFound | LeaseError::AttemptMismatch) => {
                return Err(HandlerError::retry("lease lost"));
            }
            Err(LeaseError::Client(e)) => return Err(HandlerError::retry(e.to_string())),
        }
    }
    Ok(())
})?
```

```python
from datetime import timedelta
from sepp import HandlerError, JobNotFoundError, AttemptMismatchError

@worker.handler("import")
async def import_records(payload, ctx):
    for chunk in chunks(payload):
        await process_chunk(chunk)
        try:
            # The new expiry reflects any clamping to the queue's max.
            expires = await ctx.extend(timedelta(seconds=30))
            print(f"lease renewed until {expires}")
        except (JobNotFoundError, AttemptMismatchError):
            # The lease is already gone; stop instead of working twice.
            raise HandlerError.retry("lease lost")
```

```ts
import { HandlerError, JobNotFoundError, AttemptMismatchError } from "sepp";

worker.handle("import", async (payload, ctx) => {
  for (const chunk of chunks(payload)) {
    await processChunk(chunk);
    try {
      // The new expiry reflects any clamping to the queue's max.
      const expires = await ctx.extend(30_000);
      console.log(`lease renewed until ${expires.toISOString()}`);
    } catch (err) {
      if (err instanceof JobNotFoundError || err instanceof AttemptMismatchError) {
        // The lease is already gone; stop instead of working twice.
        throw HandlerError.retry("lease lost");
      }
      throw err;
    }
  }
});
```

## Expiry and redelivery

If the lease elapses with no ack, nack or extend, sepp treats the worker as gone. What happens next depends on the attempt count: if attempts remain, the job returns to `Ready` with its `attempt` incremented and the next worker picks it up; if it was already on its final attempt, it is dead-lettered with cause `lease_expired` instead. Either way you did nothing to trigger it, a crashed worker's jobs flow back into the system on their own.

The catch is that the server cannot tell a crashed worker from a merely slow one. A worker stuck on a long call looks exactly like one that died, so its lease expires and the job is redelivered even though the original worker is still running. For a window, two workers process the same job. That is the price of at-least-once delivery, and the reason handlers must be idempotent. See [delivery guarantees](/docs/concepts/delivery-guarantees) and [idempotent workers](/docs/workers/idempotent-workers).

## Attempt fencing: FAILED_PRECONDITION vs NOT_FOUND

How does the original worker find out it lost the race in that diagram? Through the attempt number. Every reservation increments it, and every ack, nack and extend carries the attempt it was issued for. The server checks that number against the job's current in-flight state and refuses anything stale, so a slow worker can never ack a job that has already moved on. There are two distinct refusals:

- `NOT_FOUND`: there is no in-flight job with this id at all. It was already acked, or its lease expired and it has not been re-reserved yet, or it was dead-lettered, or it never existed.
- `FAILED_PRECONDITION`: the job is in-flight but under a newer attempt than yours. The lease was reassigned to another worker.

To a worker the difference rarely matters. Both mean you no longer hold the lease, so the only safe response is to stop. The clients surface them as typed errors, `JobNotFound` and `AttemptMismatch`, both under `LeaseError`, so you can catch the pair together.

<LangTabs items={['Rust', 'Python', 'TypeScript']} groupId="fencing">

```rust
use sepp_rs::client::LeaseError;

// After processing, ack the job you hold.
match client.ack(&job.ctx).await {
    Ok(()) => {} // the job is gone for good
    // The lease expired and the job was redelivered or it is already gone.
    // Either way, don't reprocess it.
    Err(LeaseError::JobNotFound | LeaseError::AttemptMismatch) => {
        eprintln!("lost the lease on {}, skipping", job.ctx.id);
    }
    Err(LeaseError::Client(e)) => return Err(e.into()),
}
```

```python
from sepp import JobNotFoundError, AttemptMismatchError

# After processing, ack the job you hold.
try:
    await client.ack(job.ctx)
except (JobNotFoundError, AttemptMismatchError):
    # The lease expired and the job was redelivered or it is already gone.
    # Either way, don't reprocess it.
    print(f"lost the lease on {job.ctx.id}, skipping")
```

```ts
import { JobNotFoundError, AttemptMismatchError } from "sepp";

// After processing, ack the job you hold.
try {
  await client.ack(job.ctx);
} catch (err) {
  if (err instanceof JobNotFoundError || err instanceof AttemptMismatchError) {
    // The lease expired and the job was redelivered or it is already gone.
    // Either way, don't reprocess it.
    console.warn(`lost the lease on ${job.ctx.id}, skipping`);
  } else {
    throw err;
  }
}
```

</LangTabs>

<Callout type="info" title="Both rejections mean: stop">
On `ack`, `nack` or `extend`, handle `JobNotFound` and `AttemptMismatch` the same way. You no longer own the job, so abandon it rather than retrying the call or finishing the work. If you use the `Worker` with auto-extend, it does this for you by aborting the handler the moment a renewal fails.
</Callout>
